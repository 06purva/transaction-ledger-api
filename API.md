# Transaction Ledger API — API Documentation

## Overview

The Transaction Ledger API provides account creation, credits and debits, balance lookup, transaction history, and atomic transfers between accounts.

- **Base path:** `/api/v1`
- **Content type:** `application/json`
- **Interactive documentation:** `/docs` while the application is running
- **Database:** PostgreSQL

For local development, start the application using the command documented in `README.md`, then open `http://localhost:3000/docs`.

## Conventions

- Account IDs are UUIDs generated by the server.
- Amounts are sent as decimal strings (for example, `"25.50"`) to avoid floating-point precision problems.
- Supported transaction types are `CREDIT` and `DEBIT`.
- Timestamps are returned in ISO 8601 format.
- Transaction history is ordered newest first.
- Error responses use an `error` field and a human-readable `message`. Validation errors may also include a `details` array.

## Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/health` | Health check |
| `POST` | `/api/v1/accounts` | Create an account |
| `GET` | `/api/v1/accounts/:id/balance` | Retrieve an account balance |
| `POST` | `/api/v1/accounts/:id/transactions` | Create a credit or debit |
| `GET` | `/api/v1/accounts/:id/transactions` | Retrieve transaction history |
| `POST` | `/api/v1/transfers` | Transfer funds between accounts |

## 1. Health check

### `GET /health`

Checks whether the HTTP service responds. The exact response shape is defined by the health handler.

## 2. Create an account

### `POST /api/v1/accounts`

Creates an account. The account ID, initial balance, and creation timestamp are generated by the system.

**Request body**

```json
{
  "name": "Asha Sharma"
}
```

Do not send an initial balance; new accounts start at `0.00`.

**Successful response — `201 Created`**

```json
{
  "id": "ACCOUNT_UUID",
  "name": "Asha Sharma",
  "balance": "0.00",
  "created_at": "2026-10-27T10:00:00.000Z"
}
```

The example illustrates the returned fields; the timestamp and ID are generated values.

**Possible errors**
- `400 Bad Request` — missing or invalid account name/request data.

## 3. Get an account balance

### `GET /api/v1/accounts/:id/balance`

Returns the current balance for the specified account.

| Parameter | Required | Description |
|---|---|---|
| `id` | Yes | Account UUID |

**Successful response — `200 OK`**

```json
{
  "account_id": "ACCOUNT_UUID",
  "balance": "125.50"
}
```

**Possible errors**
- `400 Bad Request` — account ID is not a valid UUID.
- `404 Not Found` — account does not exist.

## 4. Create a credit or debit transaction

### `POST /api/v1/accounts/:id/transactions`

Creates a transaction and updates the account balance atomically.

| Parameter | Required | Description |
|---|---|---|
| `id` | Yes | Account UUID |

**Credit request**

```json
{
  "type": "CREDIT",
  "amount": "100.00",
  "description": "Initial deposit",
  "reference_id": "deposit-1001"
}
```

**Debit request**

```json
{
  "type": "DEBIT",
  "amount": "25.50",
  "description": "Purchase",
  "reference_id": "purchase-1001"
}
```

| Field | Required | Description |
|---|---|---|
| `type` | Yes | `CREDIT` or `DEBIT` |
| `amount` | Yes | Positive amount with no more than two decimal places |
| `description` | No | Optional description, subject to validation limits |
| `reference_id` | Yes | Reference unique within this account |

**Successful response — `201 Created`**

```json
{
  "id": "TRANSACTION_UUID",
  "account_id": "ACCOUNT_UUID",
  "type": "CREDIT",
  "amount": "100.00",
  "description": "Initial deposit",
  "reference_id": "deposit-1001",
  "created_at": "2026-10-27T10:00:00.000Z",
  "balance": "100.00"
}
```

**Possible errors**
- `400 Bad Request` — invalid UUID, transaction type, amount, reference ID, or request body.
- `404 Not Found` — account does not exist.
- `409 Conflict` — reference ID already used for this account.
- `409 Insufficient Funds` — debit would make the balance negative.
- `409 Conflict` — resulting balance would exceed the supported maximum.

A rejected transaction does not create a ledger entry or change the account balance.

## 5. Get transaction history

### `GET /api/v1/accounts/:id/transactions`

Returns transactions for an account, newest first.

| Parameter | Required | Description |
|---|---|---|
| `id` | Yes | Account UUID |

**Query parameters**

| Parameter | Required | Description |
|---|---|---|
| `type` | No | Filter by `CREDIT` or `DEBIT`; omit to return both |
| `page` | No | Page number |
| `limit` | No | Number of records per page |

Example:

```http
GET /api/v1/accounts/ACCOUNT_UUID/transactions?type=CREDIT&page=1&limit=10
```

**Successful response — `200 OK`**

```json
{
  "data": [
    {
      "id": "TRANSACTION_UUID",
      "account_id": "ACCOUNT_UUID",
      "type": "CREDIT",
      "amount": "100.00",
      "description": "Initial deposit",
      "reference_id": "deposit-1001",
      "created_at": "2026-10-27T10:00:00.000Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 1,
    "totalPages": 1
  }
}
```

**Possible errors**
- `400 Bad Request` — invalid account UUID or invalid query parameters.
- `404 Not Found` — account does not exist.

The exact defaults and maximum permitted `page`/`limit` values are determined by the query validation schema.

## 6. Transfer funds (bonus endpoint)

### `POST /api/v1/transfers`

Transfers money between two different existing accounts. The debit, credit, and both ledger entries are performed in a single database transaction.

**Request body**

Use the exact source-account and destination-account property names shown by the endpoint schema in Swagger at `/docs`. The request also includes:

```json
{
  "amount": "30.00",
  "reference_id": "transfer-1001",
  "description": "Payment"
}
```

Add the source and destination account UUID fields required by the Swagger schema. Do not use the same account as both source and destination.

**Successful response — `201 Created`**

The response includes the transfer result, updated balances, and identifiers for the debit and credit ledger entries. Refer to the live Swagger schema for the exact property names.

**Possible errors**
- `400 Bad Request` — invalid request data, invalid account UUID, or source and destination are the same.
- `404 Not Found` — source or destination account does not exist.
- `409 Conflict` — insufficient source funds, duplicate transfer reference, or destination balance limit exceeded.

If any part of the transfer fails, the entire transfer is rolled back; partial transfers are not persisted.

## Common validation and integrity rules

- Account names are required.
- Account IDs must be valid UUIDs.
- Transaction amounts must be positive and support at most two decimal places.
- Account balances cannot become negative.
- A transaction reference must be unique within its account. The same reference may be used on a different account.
- Transaction records are immutable; updates and deletes are prevented at the database level.
- Balance updates and ledger writes are atomic.
- Transfers require two distinct existing accounts and are atomic.

## Error response examples

**Invalid request — `400 Bad Request`**

```json
{
  "error": "Bad Request",
  "message": "Invalid transaction details."
}
```

**Account not found — `404 Not Found`**

```json
{
  "error": "Not Found",
  "message": "Account not found."
}
```

**Duplicate reference — `409 Conflict`**

```json
{
  "error": "Conflict",
  "message": "This reference ID has already been used for this account."
}
```

**Insufficient funds — `409 Conflict`**

```json
{
  "error": "Insufficient Funds",
  "message": "The account does not have enough balance for this debit."
}
```

Error messages can vary by endpoint and validation failure. The running Swagger documentation is the authoritative source for the exact request and response schemas.
